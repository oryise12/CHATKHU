# pac_vision 현장 절차 (CALIBRATION_GUIDE)

새 장소에 Astra Pro 카메라를 놓고 **매니퓰레이터 base 좌표계로 화면의 점(물체) 좌표를 얻기까지**의 순서다.
명령·기대 출력·실패할 때 할 일·소요 시간을 단계마다 적었다. 소요 시간은 2026-10-14 한 번의 실측(같은 사람, 처음 해 본 순서)이다.
설치는 [`README.md`](README.md)의 "빠른 시작"과 "설치 상세" 절, 계산 원리와 측정 근거는 README "측정 결과와 재현 방법" 12절을 본다.

모든 명령은 같은 준비 뒤에 실행한다.

```bash
cd <저장소>/pac_vision
source <가상환경>/bin/activate
```

## 준비물

- 밝은 **무광 상자** 1개: 윗면 한 변이 10 cm 이상이고 모서리가 각진 것. 방향을 바꿔 높이를 만든다 (예: 18.1 × 11.2 × 4.8 cm 상자는 눕히면 4.8, 옆으로 세우면 11.2, 끝으로 세우면 18.1 cm).
- A4 2장, **굵은 마커** (선 굵기 5 mm 이상, 가는 펜은 화면에 안 보인다)
- 마스킹테이프, 자(30 cm 이상)와 줄자
- (확인용) **손잡이 없는 밝은 무광 컵**과 그 높이(자로 잰 값). 입구가 열린 컵은 윗면을 종이로 막는다 (아래 "알려진 한계")

## 0. 사전 점검

```bash
python scripts/check_setup.py
```

기대 출력 (끝부분):

```text
✅ pose.yaml (이 설치 자세의 정합 계수): 있음
✅ RGB 장치 후보: 이름 일치: video2 (Astra Pro FHD Camera: Astra Pro), video3 (Astra Pro FHD Camera: Astra Pro)
✅ RGB 열기: /dev/video2 프레임 읽힘
✅ depth 열기: 640x480, 유효 67 %
[요약] 모두 ✅
```

- ⚠️마다 `→ 해결 방법`이 한 줄씩 붙는다. **`pose.yaml` 없음 ⚠️**는 2단계(프리셋 복사) 또는 2-3단계(쌍 측정) 전이면 정상이다. `cam2base.yaml` 없음 ⚠️는 5단계 전이면 정상이다.
- 다른 컴퓨터 경로(OpenNI, 글꼴, YOLO 모델, RGB 장치 번호)는 커밋된 파일을 고치지 말고 `config/local.yaml`에 적는다 (`config/local.example.yaml`을 복사).
- 카메라를 다른 프로그램이 쓰는 중이면 `--no-camera`로 나머지만 본다.

## 1. 카메라 고정

- 💡 **카메라는 가능한 한 높고 가파르게(책상을 더 내려다보게) 둔다.** 근거는 2026-10-14 실측뿐이다:
  - 카메라가 책상면 위 51 cm, 광축이 수평에서 약 21° 아래였을 때 물체 윗면 depth가 12-38 %만 나왔고(컵 종이 뚜껑 12 %, 상자 38 %), 책상 depth도 27-65 %였다 (광택 책상).
  - 그 결과 물체 좌표가 카메라 쪽으로 치우쳤다 (아래 "알려진 한계").
  - 몇 도 이상이면 충분한지는 **미측정**이다. 같은 진단을 다른 각도에서 아직 하지 않았다.
- 카메라와 고정대를 단단히 조인다. **2단계부터 끝까지 카메라를 건드리지 않는다.** 움직이면 2단계부터 다시 한다.
- 물체를 놓을 영역은 카메라에서 광축 방향 거리(Z) **0.65 m 이상**이어야 한다. depth는 약 0.6 m 안쪽을 재지 못한다.

## 2. 정합 계수: 프리셋 복사 또는 정합 쌍 재기 (RGB↔depth)

RGB 영상에서 고른 점이 depth 영상의 어디인지(정합)는 카메라 실물과 설치 자세에 따라 다르다.

> ⚠️ 2026-10-23: 프리셋을 기본값으로 쓰지 않는다. 실물 1을 알아볼 표시(스티커 문구)가 미기입이고 USB 일련번호로도 구분되지 않으며, 실물 1에서도 다른 설치 자세에서는 A4 변 오차가 약 1 cm라 변 검사(5 mm)를 못 넘었다(`pose_presets/README.md`). **확실히 실물 1이고 시간이 없을 때의 리허설용**으로만 쓰고, 시연에는 아래 정합 쌍으로 그 카메라·그 자세의 `pose.yaml`을 만든다(`docs/PINCH_KHU_SETUP.md` 6절).

**카메라 실물 1(스티커로 구분)이면** 프리셋을 복사하고 2·3단계를 건너뛰어 4단계로 간다.

```bash
cp config/pose_presets/astra_unit1.yaml config/pose.yaml     # pose.yaml이 이미 있으면 덮어쓴다
```

- `config/pose.example.yaml`은 형식 예시(다른 설치 자세 값)이므로 `pose.yaml`로 쓰지 않는다.

**다른 Astra 실물이면** 프리셋을 쓰지 않는다 (좌표가 수 cm 어긋날 수 있다). 아래처럼 상자 꼭짓점을 두 창에서 찍어 쌍을 모은다.

```bash
python scripts/check_camera.py
```

```text
[pac_vision] RGB 열림 640x480 / depth(OpenNI) 열림 640x480
[RGB] (506, 271) → 이제 depth 창에서 같은 지점을 클릭하세요
[depth] (528, 280) 가운데/오른쪽 끝: 카메라 X=+0.338 Y=+0.065 Z=0.925 m  | σ 픽셀 하나 0.0 mm (유효 8/30), 5x5 중앙값 1.0 mm (유효 30/30)
  [쌍 1] dx=+22 dy=+9 px (가운데/가운데)
```

찍는 방법:
- **RGB 창 클릭 → 바로 다음 depth 창 클릭 = 한 쌍.** 순서가 바뀌면 쌍이 되지 않는다 (`(dx 쌍 아님: RGB 창을 먼저 클릭하세요)`).
- 찍는 점은 상자 **윗면의 뒤쪽(카메라에서 먼 쪽) 꼭짓점**이다. 그 너머에 더 먼 책상이 있어 depth에 경계가 생긴다.
- depth 창에서 상자 옆이 검게 비는 쪽(적외선 그림자)의 **반대쪽** 꼭짓점을 쓴다. 처음 상자를 놓을 때 한 번 보고 끝까지 같은 쪽을 쓴다.
- depth 창에서는 꼭짓점 바로 바깥이 아니라 **상자 색 영역 안쪽 1-2 px**을 찍는다. 바깥을 찍으면 뒤 배경을 읽는다 (Z가 갑자기 2 m대로 나오면 이 경우).
- RGB를 클릭한 때부터 `[쌍 N]` 줄이 나올 때까지(약 1초) 상자에 손대지 않는다.
- 잘못 찍었으면 `u`(마지막 쌍 지우기), 다 찍었으면 `q`. `data/sessions/camera_check_pairs_<시각>.csv`로 저장된다.

어디를 찍나 (모두 합쳐 20쌍 안팎, 2026-10-14은 24쌍):
- 화면 왼쪽 끝·오른쪽 끝·가까운 쪽·먼 쪽·가운데. 터미널의 위치 이름(`가운데/왼쪽 끝` 등)으로 확인한다.
- **기준 종이를 놓을 자리의 네 변 바깥 가까이** (종이에서 2-3 cm 떨어뜨림, 종이를 건드리지 않게)
- **같은 화면 높이에서 높이만 다른 쌍 2개 이상:** 낮게 놓은 상자를 뒤에, 끝으로 세운 상자를 앞에 두어 두 꼭짓점이 화면에서 같은 높이(±20 px)에 오게 한다 (RGB 창에 남는 초록 점에 맞춤).
- **같은 꼭짓점을 연속 두 번 찍은 쌍 2개 이상** (상자를 건드리지 않고). 두 쌍의 차이가 3 px를 넘는 꼭짓점은 3단계에서 자동으로 빠진다.
- 상자를 책상 밖(받침·의자 위)에 둬도 된다. 두 창에 모두 보이고, Z ≥ 0.6 m이고, 꼭짓점 너머에 더 먼 배경이 있으면 된다. 검정·광택·반투명 물체는 피한다.

실패할 때:
| 증상 | 할 일 |
|---|---|
| Z가 2 m대로 갑자기 크고 `5x5 중앙값` 표준편차가 수백 mm | depth 클릭이 상자 밖(배경). `u`로 지우고 상자 색 안쪽을 다시 찍기 |
| 가까운 쪽 책상·상자가 depth에서 검게 비어 꼭짓점이 안 보임 | 상자를 조금 뒤로 옮기거나, 반대쪽 뒤 꼭짓점을 쓴다 (광택 책상은 가까운 쪽 depth가 잘 빈다) |
| 픽셀 하나 `유효 0/30` | 꼭짓점이 경계 위라 그렇다. 5×5 중앙값 표준편차가 작으면(수 mm) 그대로 써도 된다 |

## 3. 정합 계수 저장

```bash
python tools/fit_rgb_to_depth.py data/sessions/camera_check_pairs_<시각>.csv [같은 자세의 다른 쌍 CSV ...] --write-pose
```

```text
[반복] 쌍 3·4: dx 차 5, dy 차 0 px → 제외 (기준 3 px)
[맞춤 자료 (제외 규칙 적용)] 20쌍 — 잔차 RMS / leave-one-out RMS (최대) px
    dx dist4 :  2.13 /  2.65 ( 5.1)
    dy dist4 :  1.26 /  1.59 ( 3.8)
[채택] dx 거리 식, dy 거리 식 (dy leave-one-out 고정 2.21 / 거리 식 1.59 px, 기준 차이 0.3 px)
[저장] .../config/pose.yaml  (calibrate.py·detect_objects.py가 camera.yaml 대신 이 계수를 씁니다)
```

- 채택 식의 **leave-one-out RMS가 3 px 안팎**이면 충분하다. 5 px를 넘으면 2단계에서 쌍을 더 재거나 의심 쌍을 지운다.
- `config/pose.yaml`은 git에 올리지 않는다 (설치 자세마다 다름). 형식 예시는 `config/pose.example.yaml`.
- 다시 재면 기존 파일은 `pose.yaml.bak`으로 남는다.

## 4. 기준 종이 놓기

**`config/pose.yaml`이 없으면 다음 단계의 `calibrate.py`가 실행을 거부한다.** 2단계(프리셋 복사 또는 쌍 측정 → 3단계)를 먼저 끝낸다.

- A4 두 장을 **긴 변끼리 끝을 맞춰 뒤에서 테이프로** 이어 붙인다 (틈·어긋남 없이). 두 장의 짧은 변이 일직선인지 자로 확인한다.
- 한 장에 **굵은 마커로** 대각선 두 개를 긋는다. 교차점이 base (0, 0, 0)이다. 그 종이를 긴 변 방향으로 반 접어 생긴 선 위에 X 화살표(교차점을 지나 로봇 앞쪽)를 그린다. +Y는 맞댄 종이 쪽(왼쪽)이다.
- 바깥 꼭짓점 번호를 종이 안쪽에 크게 적는다: 1 = 대각선 종이 뒤-오른쪽, 2 = 앞-오른쪽, 3 = 맞댄 종이 앞-왼쪽, 4 = 뒤-왼쪽 (위에서 볼 때 반시계).
- 종이를 카메라 앞 책상에 놓고 **변 가운데만** 테이프로 고정한다 (꼭짓점을 가리지 않게). 책상 위에는 종이만 둔다.
- 마커 선과 점은 **카메라 화면에서 보이는지 확인**한다. 2026-10-14에는 가는 펜 선이 화면에 전혀 찍히지 않았고, 교차점을 지름 8-10 mm 원으로 덧칠한 뒤에야 보였다.

## 5. 캘리브레이션

```bash
python scripts/calibrate.py
```

1. 배치 점검 화면: 가까운 쪽 거리 ≥ 0.6 m, 먼 쪽 ≲ 1.5 m, depth 유효율 확인 → **Enter**
   ```text
   [정지] 완료: RGB 30장, depth 30장 평균, 유효 69 %
   ```
2. 확대경을 보며 **교차점(base) → 꼭짓점 1 → 2 → 3 → 4** 클릭 (`u` 되돌리기, `r` 처음부터, `b` 배치 점검으로)
3. 결과 화면 (2026-10-14 1회차):
   ```text
   base 점 오차    0.1 cm ✅ (임시 기준 1.0 cm)
   A4 변 길이 cm  1-2 30.0(±0.5)  2-3 41.6(±0.7)  3-4 29.7(±0.5)  4-1 41.8(±0.7) ✅
   평면 맞춤 잔차  1.3 mm / 영역 depth 유효 47 %
   반사 검사 ✅
   ```
   눈으로 확인할 것: ○(계산으로 되돌려 그린 점)가 ●(클릭) 위에 겹치는가, 화살표(빨강 X, 초록 Y, 파랑 Z(위쪽))에서 빨강 X가 로봇 앞쪽인가, 다시 그린 외곽선이 종이와 겹치는가.
   Z 화살표는 방향 확인용이다. 높이 정확도는 확인하지 않는다.
4. **s** 저장 → `config/cam2base.yaml`, `data/sessions/<날짜_시각>.npz`
   ```text
   [안내] 재점검용 표시: 꼭짓점 4번 자리에 테이프를 붙이세요. base 좌표 (-0.148, 0.315, 0.000) m
   ```
5. (권장) 한 번 더 실행해 같은 순서로 클릭·저장한다. 두 회차 중 base 점 오차 + 변 오차가 작은 쪽을 쓴다.
   1회차를 쓰려면 `python scripts/calibrate.py --replay data/sessions/<1회차>.npz`를 실행하고 결과 화면에서 `s`를 누른다.
   2026-10-14 두 회차 차이: 회전 0.021°, 위치 0.3 mm.

실패할 때:
| 화면 | 할 일 |
|---|---|
| `반사 감지 (det<0) ⚠️` | 꼭짓점 번호 순서 확인 후 `r`로 다시 클릭 |
| `base 점 오차 ... ⚠️` | 종이가 밀렸거나 교차점 표시가 화면에서 약함. 종이·표시 확인 후 `r` (두 번 더 실패하면 `s` 두 번으로 저장하고 원인 확인) |
| `A4 변 길이 ... ⚠️` 변 하나만 | 그 변의 꼭짓점을 다시 클릭. 먼 쪽은 화면 1 px가 3-4 mm라 1 px 차이로도 허용(5-7 mm)을 넘을 수 있다 |
| `A4 변 길이 ... ⚠️` 프리셋을 썼고 다시 클릭해도 1 cm 안쪽으로 계속 넘음 | 프리셋의 알려진 한계(최대 약 1 cm). `s` 두 번으로 저장하고 8단계에서 좌표를 확인한다 |
| `pose.yaml ... 없습니다` | 2단계(프리셋 복사 또는 쌍 측정)를 먼저. 시연만 할 때는 `--allow-default-pose` |
| 다음 실행에서 `RGB 카메라를 열지 못했습니다` | 창을 `q`가 아닌 창 닫기 버튼으로 닫아 프로그램이 남아 있음. `fuser -v /dev/video*`로 찾아 종료 |

## 6. 재점검 테이프와 `--check`

- 저장 직후 **꼭짓점 4 바로 바깥**에 L자 테이프 두 조각으로 자리를 표시한다 (종이를 치워도 남게).
- 로봇은 교차점 위에 앞면을 X 화살표 방향으로 놓는다. 종이를 치울 거면 **먼저 교차점에 테이프 십자**를 붙인다.

```bash
python scripts/calibrate.py --check
```

```text
재점검: 테이프 표시(꼭짓점 4번 자리)를 클릭하세요
→ 측정 (-0.151, 0.313, 0.000) m / 기대 (-0.148, 0.315, 0.000) m / 오차 0.3 cm ✅ 보정 유지
[점] RGB (372, 310) → base (0.150, 0.108, -0.001) m  (줄자와 비교: 외삽 오차, 오프셋 제외)
```

- 오차가 1 cm를 넘으면 `⚠️ 카메라가 움직였을 수 있습니다` → 5단계부터 다시.
- 이어서 다른 점을 클릭하면 base 좌표가 나온다. 종이 밖 점은 종이 변을 자로 연장해 붙인 테이프 십자로 확인한다 (2026-10-14: 3.6-8.5 mm).
- **검증점은 동그라미를 칠하지 말고, 짧은 선이 종이 테두리와 만나는 점을 클릭한다.** 예를 들어 이음매 끝을 볼 때는 이음매를 따라 테두리까지 짧은 선을 긋는다. 2026-10-14에는 칠한 원의 중심이 이음매 끝보다 안쪽이라 1.3 cm 오차로 보였다.
- 창은 `q`로 닫는다.

## 5-1. A4 한 장, 꼭짓점 4개만 찍기 (`--layout single`)

종이 한 장만 쓸 때. 원점은 찍지 않고 **로봇 베이스 중심**으로 정한다 (`config/a4_layout_single.yaml`).

```bash
python scripts/calibrate.py --layout single
```

- 카메라 화면에서 종이의 **1 좌상 → 2 우상 → 3 좌하 → 4 우하** 순서로 꼭짓점만 클릭한다. 1-2와 3-4가 긴 변(29.7 cm)이다.
- 원점(로봇 베이스 중심)은 화면에서 긴 변 1-2의 가운데에서 위쪽(종이 바깥)으로 9 cm. 종이를 이렇게 놓는다.
- +Y = 베이스에서 종이 가운데를 보는 방향(로봇의 앞), +X = 로봇이 앞을 볼 때 오른쪽(화면에서 2 → 1 쪽), +Z 위.
  그래서 이 보정의 좌표는 시뮬레이터 world와 같은 축이다. 시뮬레이터용 `config/robot_pose.yaml`은 `x_m: 0`, `y_m: -0.003`
  (J1 축과 base_link 원점의 차이), `yaw_deg: 90`.
- 결과 화면 1번 검사는 "꼭짓점 맞춤 일관성": 꼭짓점 하나를 빼고 나머지 3개로 맞췄을 때 뺀 꼭짓점의 오차 중 최대(기준 1 cm).
  큰 꼭짓점 번호가 나오면 그 번호 키(1~4)로 그 꼭짓점만 다시 찍는다.
- 두 장 배치보다 기준이 작아 기울기 오차가 커진다.

## 5-2. ArUco 보정판, 클릭 없이 (`--layout aruco`)

A4 한 장에 ArUco 마커 4개(`DICT_4X4_50` ID 1~4, 한 변 95 mm)를 인쇄한 보정판을 쓴다. 클릭 대신 정지 화면에서 마커를 찾아
각 마커 **중심**(서브픽셀 꼭짓점의 대각선 교점)을 기준점으로 쓴다. 계산·검사·저장은 5-1과 같다 (`config/a4_layout_aruco.yaml`).

```bash
python tools/make_aruco_board.py ~/aruco_board.pdf     # 인쇄물 (배치 파일의 값으로 만든다, 실제 크기 100 %로 인쇄)
python scripts/calibrate.py --layout aruco             # 배치 점검 → Enter → 마커 자동 검출 → 검사 5가지 → 모두 ✓이면 s
```

- 인쇄 후 가운데 50 mm 눈금과 마커 한 변(9.5 cm)을 자로 확인한다.
- 놓는 자리는 5-1의 A4와 같다: 가로로 놓고 인쇄된 화살표("로봇 쪽")가 로봇을 보게. ID 1·2·3·4가 꼭짓점 1(좌상)·2(우상)·3(좌하)·4(우하) 쪽에 온다.
  원점(로봇 베이스 중심)은 로봇 쪽 긴 변 가운데에서 종이 바깥으로 9 cm. 축도 5-1과 같다.
- 마커 중심 base 좌표: ID 1 (+0.0925, 0.1425), 2 (−0.0925, 0.1425), 3 (+0.0925, 0.2475), 4 (−0.0925, 0.2475) m.
- 마커를 다 못 찾으면 이유(안 보임 / 같은 번호가 두 개 / 너무 작음)를 보여 준다. `b`: 새 정지 화면, `c`: 마커 중심을 손으로 클릭.
  결과 화면의 `r`은 새 정지 화면에서 다시 찾기, 번호 키는 그 마커 중심만 손으로 클릭.
- **마커끼리 붙이면 안 된다**: 검은 테두리가 합쳐져 하나도 검출되지 않는다(2026-10-26, 인쇄 그림·실제 카메라 화면 합성 모두 0개).
  그래서 짧은 변 방향은 여백 5 + 마커 95 + 사이 10 + 마커 95 + 여백 5 mm, 긴 변 방향 사이는 90 mm다. `make_aruco_board.py`는 사이가 5 mm보다
  좁으면 만들지 않는다.
- 2026-10-26 16:09 프레임(카메라 실물, 뒤집어 단 자세)의 종이 자리에 보정판을 합성한 시험: 4개 모두 검출, 화면 한 변 49–77 px,
  중심 오차 0.14–1.6 px(1.6 px는 로봇 받침 옆, 바깥이 어두운 마커 2). 손 클릭 오차(3–5 px)보다 작다. 실제 인쇄물로는 아직 재지 않았다.
- 마커 중심 사각형(10.5 × 18.5 cm)은 A4보다 작아서 화면 크기 검사 기준을 40 px로 둔다(`short_side_min_px`).
- 다른 종이에 같은 번호(예: 고정 표지 ID 1)가 함께 보이면 어느 것이 보정판인지 몰라 멈춘다. 보정하는 동안은 치운다.

## 6-1. 고정 표지로 정합 확인 (시뮬레이터가 실행 중에도 쓰는 독립 점)

`--check`는 사람이 테이프 점을 클릭하는 점검이다. 시뮬레이터가 스스로, 시작할 때와 실행 중에 카메라가 밀리거나 돌지 않았는지 보려면 보정에 쓰지 않은 **ArUco 고정 표지**를 둔다.

```bash
cp config/markers.example.yaml config/markers.yaml              # git 제외. id·크기·잰 좌표를 적는다
python scripts/check_markers.py --sheet ~/markers_sheet.png     # 인쇄용 표지 (100 % 크기로 인쇄, 한 변을 자로 확인)
python scripts/check_markers.py                                 # 표지별 이미지 오차(px)·책상면 오차(mm) → config/markers.check.yaml
```

- 표지는 보정 종이 밖, 로봇·손이 가리지 않는 책상 위 두 곳 이상에, 서로 멀리 평평하게 붙인다. 화면에서 한 변이 30 px 이상 보여야 한다(비스듬히 보면 짧아진다. 1 m 거리면 10~12 cm).
- 각 표지 **중심**의 base_ref 좌표(m)를 줄자로 재서 `markers.yaml`의 `base_m`에 적는다. 이 좌표가 보정과 따로 잰 "정답"이다.
- 판정(`src/pac_vision/markers.py`): 보이는 표지가 `min_visible`개 이상이고 모두 `max_pixel_px`·`max_desk_mm` 안이면 확인됨, 하나라도 밖이면 어긋남(카메라 이동·회전, 표지 이동, 보정 오류 중 하나), 적게 보이면 확인할 수 없음.
- 허용오차 8 px / 10 mm는 출발값이다. 카메라를 건드리지 않고 5회 이상 잰 값의 분포로 정한다. 합성 시험(약 1.3 m에서 비스듬히 보는 장면)에서는 카메라 0.5° 회전, 2 cm 밀림부터 어긋남으로 판정했다(실제 카메라 값이 아님).
- `cam2base.yaml`에는 보정에 쓴 RGB 장치의 신원(장치 이름, USB 포트 by-path)이 함께 저장된다. 시뮬레이터는 다른 포트·다른 카메라로 보이면 그 보정을 쓰지 않는다.
- 카메라는 한 프로그램만 연다(`$XDG_RUNTIME_DIR/pac_camera.lock`). 시뮬레이터가 켜져 있으면 이 스크립트들은 시작하지 않는다.

## 7. 물체 좌표 (현재 시나리오에서는 쓰지 않음)

```bash
python scripts/detect_objects.py                          # 보기만
python scripts/detect_objects.py --ros                    # ROS 2 발행 (먼저 source /opt/ros/<humble|jazzy>/setup.bash)
```

```text
[pac_vision] 보정 읽음: config/cam2base.yaml (2026-10-14 04:15, base 점 오차 0.1 cm)
[pac_vision] YOLO 모델 로드 완료 (CPU)
[선택] cup  base (0.348, 0.281, 0.074) m
```

1. **빈 책상:** 박스가 뜨지 않아야 한다. `z`를 누르면 책상면 z 분포(책상면 ±2 cm 점만)와 1 cm 넘게 뜬 점의 비율이 나오고, 높은 픽셀이 보라색으로 칠해진다. 책상 위에 보라색이 없으면 통과다 (책상 너머 소파·선반은 보라색이 정상).
2. **컵:** 컵을 테이프 표시에 놓고 박스를 클릭한다. z는 컵 높이와 몇 mm 안이어야 한다. x·y의 카메라 쪽 치우침은 아래 "알려진 한계"를 본다.
3. 물체를 옮기면 선택이 따라가고(`[추적] ID를 잃어 마지막 위치에서 가장 가까운 cup 검출로 대체했습니다`), 가리면 약 1초 뒤 `⚠️ 선택 물체를 놓침. 발행 중지`, `c`로 해제된다.
4. `--ros`: 다른 터미널에서 `ros2 topic echo /pac/target_point` → `frame_id: base_ref`, 값이 화면과 같아야 한다.

실패할 때:
| 증상 | 할 일 |
|---|---|
| `[선택] cup  좌표 없음 (depth 부족)` | 물체가 너무 가까움(Z < 0.6 m), 검정·광택·투명 물체, 또는 너무 납작함(1 cm 이하). 더 먼 곳에 두거나 다른 물체 |
| 뒤집은 컵 등이 박스로 안 잡힘 | YOLO(COCO)가 그 모양을 컵으로 모름. 바로 세운 컵에 종이 뚜껑 |
| `⚠️ ... pose.yaml이 없습니다` / `보정 때와 다른 정합 계수` | 정합을 다시 쟀다면 `calibrate.py --replay <세션> --use-current-config`로 보정 갱신 |

## 알려진 한계 (요약)

자세한 근거는 README ["알려진 한계"](README.md#알려진-한계-2026-10-14-팀-공유-필요) 절.

- **물체 x·y가 카메라 쪽으로 치우친다.** 카메라가 낮게(광축 약 21°) 보면 물체 윗면 depth가 일부만 나와, 윗면 중심이 물체 깊이 방향 크기의 약 절반만큼 카메라 쪽으로 밀린다 (뚜껑 컵 −2.5 ~ −3.8 cm, 상자 −4.3 ~ −5.0 cm). x와 높이(z)는 3 mm 안이다. 받는 쪽(경로 계획)은 접근 여유를 둔다. 계산 방식 개선은 팀 안건이다.
- **입구가 열린 용기**는 그 높이에 테두리만 있어 카메라 쪽 테두리로 반지름만큼 치우친다 (컵 약 −5 cm).
- **정합 프리셋은 카메라 실물 1 전용**이다. 프리셋으로 캘리브레이션하면 A4 변 오차가 최대 약 1 cm라 변 검사(기준 5 mm)가 ❌로 나올 수 있다. 팀 허용 오차는 미정.
- `show_base_coords.py`는 동작만 확인했고 점별 오차 측정은 아직 없다.
